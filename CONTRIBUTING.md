# Contribution Guidelines
New contributors are always welcome (and desperately needed)

## Ways to contribute
- find issues and fix them
- find issues and raise a ticket (issue tab)
- create tests that may be missing
- improve the ui
- improve the docs

## Pull Requests
- Update the docs (if your changes affect the users this is a MUST)
- Link the dev branch on the issue that you are working on
- If you're fixing an issue, open an issue as well or link existing one

## Issues
- Avoid duplicates (check for open issues before creating another one)
- Follow the templates
- Add sufficient information and add logs/screenshots where applicable

## How to start
### What i recommend
- Use the devcontainer at the root of the repo to start developing (this is optional but i would urge you to use it)
- Raise issues if you find any
- Ask for help, i know it can be daunting to start contributing to a new unfamiliar repo and if you happen to get stuck dont be afraid to ask for help on the issue that you are stuck on (you can add the `needs assistance` label on the issue)

### What i would advise against
- Do not use the devcontainer with goland (just doesnt work i have tried and went back to vscode)
- Be careful of your git credentials when using vscode from flatpak (it may not be setup properly)
